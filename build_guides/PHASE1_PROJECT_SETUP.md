# PHASE 1 — Project Setup

> **Build guide for the from-scratch reconstruction of the arXiv Paper Curator (Agentic RAG).**
> This phase creates the empty, installable project skeleton. It is **documentation + configuration only** — no application code is written here.

---

## 1. Phase Objective

Create the foundational project skeleton that every later phase builds upon:

- A valid, installable Python package using **`uv`** as the package manager and build backend.
- Python version pinned to `>=3.12,<3.13`.
- The `src/` package layout with `__init__.py` files so the codebase is importable as `src.*`.
- Core dependency declarations (FastAPI, SQLAlchemy, LangGraph, OpenSearch, OpenAI, etc.).
- `.env.example` (variable **names** only — never secrets), `.gitignore`, `Makefile`, and a README skeleton.

**Why this phase comes first:** Every subsequent phase (configuration, database, schemas, services, routers) adds code *into* this skeleton. A clean, pinned toolchain avoids dependency drift and import-path problems later. The `src/` layout is required because the entire reference project imports modules as `src.config`, `src.db.*`, `src.schemas.*`, etc.

## 2. Prerequisites

- **PHASE 0** complete — you have read [`PHASE0_RECONSTRUCTION_MANUAL.md`](../Agentic-RAG-project-agentops/PHASE0_RECONSTRUCTION_MANUAL.md) and understand the architecture and the 20-phase build order.
- **Tooling installed on the machine:**

> **Important:** In this phase you only create the top-level files (`pyproject.toml`, `.env.example`, `.gitignore`, `Makefile`, `README.md`) and the **`src/` package with its `__init__.py` files**. The `db/`, `models/`, `repositories/`, and `schemas/` subdirectories are created in later phases — but you may create their empty `__init__.py` files now if you prefer to establish the full package tree up front. The reference project's `src/__init__.py` is **empty** (it exists as a package marker).

**Explanation:**
- `[project]` declares the package metadata and the full runtime dependency list. `requires-python = ">=3.12,<3.13"` pins the interpreter range.
- `[dependency-groups]` declares dev and viz tooling groups (uv's replacement for `dev` extras). `dev` includes pytest, ruff, mypy, pre-commit, and test utilities.

- `[tool.pytest.ini_options]` sets `asyncio_mode = "auto"` (so async tests run without explicit markers) and points pytest at `.env.test` for env vars.
- `[[tool.uv.index]]` + `[tool.uv.sources]` route `torch`/`torchvision` to the CPU-only PyTorch index — this is the reference project's approach to avoiding CUDA bloat.
- `[tool.mypy]` sets `explicit_package_bases = true` (needed for the `src/` layout) and `ignore_errors = true` (mypy is configured but not enforced).

```makefile
.PHONY: help start stop restart status logs health setup format lint test test-cov clean

# Default target
help: ## Show this help message
	@echo "Available commands:"
	@grep -E '^[a-zA-Z_-]+:.*?## .*$$' $(MAKEFILE_LIST) | awk 'BEGIN {FS = ":.*?## "}; {printf "  \033[36m%-15s\033[0m %s\n", $$1, $$2}'

# Service management
start: ## Start all services
	docker compose up --build -d

stop: ## Stop all services
	docker compose down

restart: ## Restart all services
	docker compose restart

status: ## Show service status
	docker compose ps

logs: ## Show service logs
	docker compose logs -f

# Health checks
health: ## Check all services health
	@echo "Checking service health..."
	@curl -s http://localhost:8000/health | jq . || echo "API not responding"
	@curl -s http://localhost:9200/_cluster/health | jq . || echo "OpenSearch not responding"
	@curl -s http://localhost:8080/api/v2/monitor/health || echo "Airflow not responding"
	@curl -s http://localhost:11434/api/version | jq . || echo "Ollama not responding"

# Development
setup: ## Install Python dependencies
	uv sync

format: ## Format code
	uv run ruff format

lint: ## Lint and type check
	uv run ruff check --fix
	uv run mypy src/

test: ## Run tests
	uv run pytest

test-cov: ## Run tests with coverage
	uv run pytest --cov=src --cov-report=html

# Cleanup
clean: ## Clean up everything
	docker compose down -v
	docker system prune -f
```

**Explanation:**
- `make setup` runs `uv sync` to install dependencies.
- `make format` / `make lint` / `make test` wrap ruff, mypy, and pytest.
- The `start`/`stop`/`health`/`logs` targets reference `docker compose` — those become meaningful in PHASE 16 (Docker), but the targets are defined now so the Makefile is complete.

## 8. Common Pitfalls

- **Python version mismatch.** The project requires `>=3.12,<3.13`. If `uv` picks a different interpreter, install Python 3.12 and/or add a `.python-version` file with `3.12`.
- **`uv` not installed.** `uv sync` will fail. Install uv first (`pip install uv` or the official installer).
- **Committing `.env` with real secrets.** `.env` is git-ignored; only `.env.example` (placeholders) should ever be committed.
- **Missing `src/__init__.py`.** Without it, `import src` fails and every later phase's `from src.* import ...` statements break. Ensure the package markers exist.
- **torch installs CUDA version.** If you omit the `[[tool.uv.index]]` / `[tool.uv.sources]` CPU-only torch configuration, `uv sync` may pull the large CUDA build. Keep the pytorch-cpu index config.
- **Forgetting `[tool.pytest.ini_options]`.** PHASE 17 tests rely on `asyncio_mode = "auto"` and `env_files = ".env.test"`. Include it now to avoid rework.
